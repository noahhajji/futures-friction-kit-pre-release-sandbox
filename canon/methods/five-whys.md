# Five Whys

Get beneath a product's inherited form by following its stated purpose and assumptions towards the need it is meant to serve.

## When it helps

- Within first-principles work, when an explanation stops at "because this is how the product works".
- To investigate a problem, provided causal claims are supported by evidence.

## Start with

- One specific statement that someone can explain.
- For product inquiry, a form or design choice.
- For an actual failure, observations of what happened.

## Working with the method

- Ask about the reason in the previous answer. Vary the wording so the inquiry remains purposeful: "What does that enable?", "Why is that necessary?" or "What need would remain if that disappeared?"
- Mark each answer as an observation, interpretation, assumption or value commitment. Branch when there are several explanations. Do not force a complex situation into one causal chain.
- When an underlying need becomes clearer, separate what should be preserved from how it is currently delivered. Return to first principles or Reimagine if the user wants to explore another form.
- Stop when an answer needs external evidence, reaches an explicit value choice or no longer changes the understanding. The number five is a prompt to go deeper, not a completion requirement.

## Useful questions

- "Why must someone visit the archive to access this knowledge?"
- "Is that necessary for the need itself, or a consequence of the way we built the product?"

## Capture

- Starting statement.
- Questions and answers.
- Evidence status at each link.
- Alternative explanations.
- Underlying need hypothesis.
- Preserve and reconsider choices.
- Unresolved question.

## Worked example

A constructed illustration, not a universal history of news archives.

- Why visit an archive? Because knowledge is stored as finished articles.
- Why only finished articles? Because publication was the organising unit.
- Why should that unit also determine access? The team recognises an inherited design assumption.
- Emerging need: reliable access to established knowledge in the user's context.
- Preserve provenance and accountability; investigate whether retrieval needs to remain article-led.

## Quality boundaries

- The method does not prove a root cause or a "true" user need.
- Do not supply invented answers to reach five, lead the user towards AI as a predetermined solution, or turn inquiry into blame.
- First principles is the broader approach; Five Whys is one technique that can support it.
